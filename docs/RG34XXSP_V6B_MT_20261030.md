# RG34XXSP v6b：加入 MT 管理器

日期：2026-10-30。用户在 v6a 完成后回复确认“MT 一并预装”。当前名单为原六款、天马 G 与 MT，共八款；MT 不再只是预装候选，但其全程十字键验收边界没有变化。

## 变化与输入

采用此前已安装、按 API 29 验签并读回一致的官方 MT 2.26.10 / 26101061，包名 `bin.mt.plus`，37,521,106 字节，SHA-256 `8f83cef8ac63f76a81e1fee3ededb213f6ba43cc19761e38bc4e567c87edd47d`。APK 含 armeabi-v7a，最低 API 21；保持原签名，不复制现机账号、偏好或文件。详细功能边界见 [MT 测试记录](RG34XXSP_MT_CLEANUP_20261030.md)。底栏和侧栏顶部部分功能仍需 Select 长按虚拟鼠标。

[八款预装锁](../config/pegasus/preinstall-apks-v6b.json) 要求前七项与已验证 v6a 完全一致，只允许添加此 MT。旧七款锁、v6a 工具与镜像继续保留。新的 `tools/package_h700_v6b.py` 校验 v6a 的原始镜像锁、分区及资源清单和全部输入分区，复制 system 到新的 WSL 工作目录，仅修改五个文件：MT APK、应用安装表、资源校验表、版本 build.prop 与首次启动安装脚本。vendor、硬件前缀、干净 userdata/ROMS/GPT 均保留原字节。

首次启动脚本改为 `h700-preinstall-v6b.sh`（镜像运行路径仍为 `/system/bin/h700-preinstall.sh`），只在 v6b release guard 下运行。安装器目录锁改为内核文件锁；Android mksh 需在 flock 调用处显式继承 fd 8，已在当前样机的自有临时夹具验证并发排斥及进程退出后重新取得锁。第一次未显式传 fd 的原型失败并已保留；未宣称断电或安装中途恢复已通过。原 v6a 脚本没有改写。

没有重新编译 AOSP、重打框架 DEX、修改模拟器/输入/硬件策略，也没有刷写设备。八款 APK 仍是只读资源中的原签名安装包，首次启动由 PackageManager 安装到 data；MT 的隐私协议等首开交互留给用户完成。

## 封装与校验

```powershell
.\tools\build_h700_low_pressure.ps1 -Targets H700ReleaseImageMT -Execute
```

CPU 0–1、合计单核、nice 19、单任务、RAM 6GiB、swap 512MiB、空闲 I/O，限制不放宽。没有可读取的主机电压测量；没有调整电压/超频。压缩时直接顺序读取校验过的分区范围，计算整镜像 SHA，输出 gzip 后完整解压并逐范围及整体再核验，避免在 D: 再生成 32GB raw 副本。

工作目录为 WSL `/home/lpf/h700-release-v6b-20261030/`，输出 `out/h700-v6b-preinstall-20261030/`。首次中断原型在 WSL `/home/lpf/h700-release-v6b-20261030-fd8-prototype/`，原始设备锁测试及构建日志仅留本地。这些材料按保留规则保护，不上传 Git。源码、配置、元数据和脱敏报告入 Git；APK/镜像不上传。
