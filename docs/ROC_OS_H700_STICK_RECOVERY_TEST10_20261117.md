# Test10：公共摇杆恢复候选整卡镜像

2026 年 11 月 17 日，按用户要求将新的公共摇杆恢复候选重新封入一份十二机型共用整卡镜像。Test10 已完成整卡封装、独立完整镜像验证和 Windows SHA256 核对，全部通过。当前没有物理硬件连接，34XXSP 与 35XX H 的实际摇杆恢复仍待刷机确认。

用户实测 Test9 在 34XXSP 和 35XX H 上均无摇杆输入，先前正常的 34XXSP 也发生回归。保留的 Test8 现场记录显示，摇杆模块已加载、Linux 与 Android 的轴映射存在，操作期间十字键等事件正常，却没有模拟轴或 L3／R3 事件。故障时没有 ADC／CCU／GPIO 读回，尚不能确定唯一物理触发原因。Test9 的离线通过记录继续保留，不作为实体摇杆修复通过的证据。

新候选把 L3／R3 的 GPIO 采样、释放与去抖从 ADC 门控中分离，避免 ADC 异常同时吞掉点击输入。恢复仅覆盖本模块已经持有的 channel0 ADC 状态：原设备树仍为 disabled、时钟已开且没有其它通道或比较器参与时，才允许进行受限恢复；不修改 CCU 或接管 GPIO 复用。恢复保留既有中心校准，轴重新经历三帧真实回中后放行。寄存器写入最多每秒一次，连续异常最多三次，连续健康一秒后才恢复预算。实际 PM 恢复、方向、回中、点击和故障条件均待新包实体确认。

整卡直接以冻结的 Test8 为父包，纳入 Test9 的原样 2 GiB swap 前缀和新摇杆模块；没有把 Test9 旧模块再次打包。相对 Test8 仅更新三个 payload：

- boot ramdisk 的 `grow/h700-optional-axes.sh`。
- vendor 的 `/modules/h700_stick_axes.ko`。
- vendor 的 `/bin/rgsp-stick-axes.sh`。

新模块为 30800 字节，SHA256 为 `0c80d226a0be754997e987234e61032620448246bec467611b0a6506c0c964e0`。两份加载脚本相对 Test9 仅替换所固定的模块 SHA256；早期 helper 的 swap 前缀字节相同。引导头、环境、U-Boot、内核、DTB、原始组件位置、机型菜单及加载提示保留；system、userdata、GPT，以及 Navigation18／framework／双 ABI ART／Lid4／时间／USB／user 与 Enforcing 安全配置已由独立验证器确认保持父包字节一致。
