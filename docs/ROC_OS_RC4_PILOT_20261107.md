## 已验证与尚未验证

本镜像通过完整 user 构建、实际 ARM64/ARM32 产物与依赖检查、116 个 APK 签名检查、完整整卡范围和 gzip 解压校验。真机已通过干净首启、自动初始化、Mali/AT4K、Home 下拉、Select 鼠标、菜单十字键、亮度/B 返回、合盖息屏与开盖唤醒/A 解锁。两次正常重启后服务保留，Thermal HAL 五项温度有效，采样崩溃缓冲区为空。

Wi-Fi 首次连接能联网，但首次缓冲保存失败，随后重启丢失网络。重新连接后保存与再重启自动联网通过。**第一次干净启动写入失败的机制仍未消除，必须保留为内测缺陷；不能要求测试者反复重连后就记为通过。**

以下事项仍阻断正式发行：

1. 干净首次连接的 Wi-Fi 保存及跨重启复验。
2. bringup wake lock 仍保留；深睡、待机耗电、完整充电/低电与温控保护未完成。本轮合盖通过仅代表息屏和唤醒。
3. 当前 RC4 同镜像的完整音频/耳机、外设范围、TF2/普通应用存储和多轮冷启动仍需验收；旧 eng 的结果不直接转计。
4. 实卡恢复/升级、许可/分发清单、独立干净重建对照和最终同镜像验收未关闭。
5. 调试入口策略未转为正式发行策略：镜像仍启用认证 USB ADB，并预置本工作站公钥；root/TCP ADB 关闭、SELinux Enforcing。此包不包含私钥。对外包应移除本机公钥种子、确定 USB 调试策略并重验；该改动会产生新镜像与新哈希。
6. 当前为直接源码构建的 `dev-keys` 元数据，实际 APK 已验证为 ROC 生产签名身份，并非据标签推断使用公开测试密钥；正式签名封装/元数据流程与发行门禁仍须收口，不能仅改显示字符串冒充完成。

## 小范围测试安排

先使用少量同硬件版本、可恢复的测试设备和至少 64 GB 的专用测试卡。烧录会覆盖目标卡；测试卡先备份，首次只插 TF1，TF2 留空。保持镜像原文件名及 SHA，记录是否首次使用这份全新镜像，避免把后续已修正状态当成干净首启结果。

按下列顺序记录，每项写明“通过 / 失败 / 未测”：

| 项目 | 方法 | 记录重点 |
| --- | --- | --- |
| 干净首启 | Rufus 4.7 烧录核对过 SHA 的 gzip，正常按电源；首次扩容和初始化允许等待数分钟 | 到达桌面耗时；是否需要额外手动设置；超时保持 USB 抓日志，不执行音量组合键 |
| 自动导航 | 首次进入桌面后测试 Home/菜单长按、Select 长按后松开、十字键移动和 B 退出 | 未手动启用辅助服务也应生效；分别测桌面和设置 |
| Wi-Fi 首次保留 | 首次连接网络，联网后等至少 30 秒，正常菜单重启 | 是否自动连接，是否要求再次输入密码；首次失败必须登记 |
| 亮度与合盖 | 下拉栏调暗/调亮/B 返回；合盖约 10 秒再开盖，A 解锁 | 背光变化、恢复、闪烁/重启；不计作深睡测试 |
| 日常使用 | 使用测试者已有、来源合规的应用，观察音频、菜单和稳定性 | 卡顿、崩溃、异常发热、耳机识别；未测外设明确留空 |
| 文件保留 | 在自己的测试目录保存/改名一个小文件，正常重启后核对 | 不清理或格式化其他卷；TF2 另安排非破坏性测试 |
| 无电脑操作 | 后续冷启动与基本操作不连接 ADB，完成后再接 USB 收集状态 | 是否依赖电脑；与首次带 USB 调试记录分开 |
