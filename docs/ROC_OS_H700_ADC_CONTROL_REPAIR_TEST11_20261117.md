# Test11：摇杆 ADC 控制位修复

2026-11-17，RG35XX H 的 Test10 USB 现场确认：L3、R3 和十字键有原始事件，四个模拟方向轴没有事件。模块已经加载，型号为 `rg35xxh`，四轴能力和 Android 映射齐全。

## 已定位的原因

内核诊断持续报告 `reason=adc-control`、`raw_valid=0`、`ctrl=0x00890000`，三次恢复全部失败，随后进入恢复预算保护。中心校准为 `2092/2058/2066/2036`，没有越界。

Test8～Test10 的公共驱动把模式位按第 8～9 位处理，使用 `0x10300/0x10200` 判断 ADC 是否处于启用的连续模式。H700 的实际 GPADC 模式位是第 18～19 位，启用位是第 16 位。因此现场控制值本来满足连续采样条件，却被错误拦截。Test10 已将 L3/R3 与模拟轴采样分开，解释了本次“下压正常、方向无效”的组合。

这个错误来自沿用 BSP 通用头文件的旧模式掩码，没有对照实际写寄存器函数。以下原始实现相互吻合：

- Linux 4.9 BSP `drivers/input/sensor/sunxi_gpadc.c` 的 `sunxi_gpadc_mode_select()` 实际写入 `mode << 18`。
- 同套 U-Boot 的 `drivers/phy_key/sunxi_gpkey.c` 连续模式设置清第 18 位、置第 19 位及第 16 位。
- Linux 上游 `drivers/iio/adc/sun20i-gpadc-iio.c` 定义 `MODE=GENMASK(19,18)`、`EN=BIT(16)`，第 23 位为自动校准。

修复统一使用模式掩码 `0x000c0000`、连续值 `0x00080000`、启用位 `0x00010000`。配置与读回检查一起修改，保留自动校准等其他位；不取消所有权、时钟、回中、休眠和有界恢复保护。

## 测试边界

旧主机测试把 MMIO 当作普通数组，错误位也可以原样读回，未模拟真实硬件的保留位行为。新测试须模拟第 8～9 位写入无效，并以现场 `0x00890000` 验证冻结 Test10 的失败及新候选的方向事件；也检查非连续模式和禁用状态仍受保护。

40XX V 可用的用户反馈不能证明所有双杆型号已通过，也不足以解释该反馈对应的实际运行状态。本次故障结论依据当前 35XX H 的明确文件身份、实际按键操作及内核控制状态。

## 在线维护和集成

当前正式 `user` 系统保持 SELinux Enforcing，ADB shell 无模块替换和寄存器写权限；现有系统未提供可用的在线维护入口。因此 USB 诊断可以完成，直接推送模块文件不能让正在运行的驱动生效。现场没有重启、重载模块或调整安全设置。

新候选和后续 Test11 整卡包分别使用独立目录，保留 Test10 原始镜像、源码和收据。整卡集成需同时替换模块、早期启动 helper 及 Android loader 的模块校验值；继承十二机型选择、三档试屏、加载提示、导航保护和默认 2 GiB swap。当前现场已看到 `SwapTotal=2097148 KiB`，说明 Test10 的 swap 在该机器实际启用。
