# RG34XXSP 合盖息屏、开盖唤醒

日期：2026-10-29。独立于亮度、蓝牙和音频修改。按用户要求，先提交并推送硬件盘点 `453aa443173ceba568f42c68433938cb456b8dd5`，标签 `baseline/rg34xxsp-hardware-audit-20261029`，之后才开始本项。

## 行为与范围

新增独立平台签名应用 `com.roc.rgsp.lid` / `H700Lid`，当前以数据应用安装。只有 `ro.product.device=rgsp`、明确设置 `persist.vendor.rgsp.input_profile=rg34xxsp` 且厂商 Hall 接口可读时运行。未来产品包也加入 H700Lid；未更新原 IMG 或写 system/vendor/boot。

- 读取 `/sys/class/power_supply/axp2202-battery/hallkey`，已由用户实测确认 **0=合盖，1=开盖**。
- 每 250ms 采样，连续稳定至少 250ms 后处理边沿，通常约 250…500ms 响应。
- 合盖且屏幕交互开启时，调用 Android 10 `PowerManager.goToSleep(uptime, GO_TO_SLEEP_REASON_POWER_BUTTON, 0)`。
- 开盖且已睡眠时，调用 `PowerManager.wakeUp(uptime, WAKE_REASON_POWER_BUTTON, "H700Lid:OPEN")`。开盖只唤醒，保留原锁屏与 A 解锁。
- 已经熄屏时合盖不唤醒；已经亮屏时开盖不让其反向熄屏。稳定状态不重复请求，不注入电源键或其他按键。
- 服务启动时盖子已打开，不会打断用户此前手动熄屏；初始关闭状态则按需熄屏。读到异常值时不请求任何电源动作，并重新等待稳定采样。
- 使用低优先级前台通知保持服务可运行。没有唤醒锁，没有写背光、GPIO、PWM、`/sys/power/state` 或解除现有 bringup 锁。

调用的方法和原因常量已核对当前保留的 Android 10 `PowerManager.java`：sleep reason=4，wake reason=1。使用平台签名获取 DEVICE_POWER，实机已确认权限授予、隐藏 API 调用成功。没有为此更改全局隐藏 API 策略。

测试模式只在 `ro.debuggable=1` 且目标 profile 通过时允许，读取应用自己的固定私有夹具文件，120s 自动停止，不改持久启用偏好。服务不导出，普通应用不能发起该测试。最终已退出夹具模式。

首轮用覆盖写入更新夹具时曾短暂读到空文件，服务正确忽略，未引发电源动作；保留了该证据。最终循环改用原子替换。诊断分别显示 readErrors 与 powerErrors，避免把一次无效采样当作电源调用失败。

## 屏幕与待机影响：还未完成的部分

本项接通的是 **现有电源键对应的 Android 睡眠/唤醒流程**。受控合盖后：

- PowerManager `Asleep`，Display Power `OFF`。
- Android Wake Locks 为 0，显示与应用 wakelock 的 suspend blocker 均释放。
- 内核仍持有原有 `rgsp_android_bringup`；本次未解除。
- disp 仍显示 `unblank`、LCD `backlight(50)`，可见 BUF layer 条目消失，但显示 IRQ 仍增加。该字段本身不能确定真实背光供电；结合持续中断，不能宣布显示硬件完全关断。用户此前电源键测试看到屏幕变黑，也不能替代背光/功耗测量。

因此 **Android 息屏与恢复通过，低功耗待机、真实背光关断、内核深度挂起未通过验收**。

当前服务用 Handler 轮询，不持有 WakeLock，也没有设置唤醒闹钟。进入真正内核挂起后 Handler 不执行；除非 Hall 已能作为内核唤醒源，否则单靠此服务无法保证开盖唤醒。不能为了让轮询继续运行而补一个常驻唤醒锁。

后续应单独核对 HWC primary display 的电源关断、LCD/backlight 与 suspend；查清实际 Hall GPIO/IRQ 及 wakeup 能力，再优先接入标准 SW_LID/内核唤醒链路。确认恢复路径且有人在场后，才移除 bringup 锁并测试 USB 拔线、合盖待机、开盖唤醒和续航。不要直接照搬其他 H700 机型的 Hall 引脚或在无人看护时强制 mem。

## 构建、来源与回退

```powershell
.\tools\build_h700_low_pressure.ps1 -Targets H700Lid -Execute
```

维持原 CPU 0–1、总配额 1 核、`-j1`、6GiB RAM、512MiB swap、nice19、空闲 I/O。这个目标只重建并签名 H700Lid，不重建导航或整系统。产物在 `out/rg34xxsp-lid-20261029/`。

应用源码、Android.bp、产品包声明已同步到保留 AOSP 树。写入前核对旧产品文件等于盘点检查点，并备份到私有 `lid-20261029/native-before/`。原 364 文件冻结快照保持不变。[组件锁](baselines/rg34xxsp-lid-20261029/component-lock.json)、[源码锁](baselines/rg34xxsp-lid-20261029/source-lock.json)及[验证摘要](baselines/rg34xxsp-lid-20261029/validation.json)固定本项。

以下命令都必须先按当前基线核对目标 USB 身份；`<serial>` 是当前已核对设备的占位符，不能使用历史默认设备：

```text
adb -s <serial> shell dumpsys activity service com.roc.rgsp.lid/.LidService
adb -s <serial> shell am start-foreground-service -n com.roc.rgsp.lid/.LidService -a com.roc.rgsp.lid.DISABLE
adb -s <serial> shell am start-foreground-service -n com.roc.rgsp.lid/.LidService -a com.roc.rgsp.lid.ENABLE
```

停用已实测，写入应用自己的 enabled=false 并停止服务，后续启动广播也尊重该设置。仅 force-stop 不是持久产品配置。若需要完整撤回，本轮安装前确认该包不存在，可撤掉本轮新增包；其他应用、导航、按键映射与系统分区无需回退。

原始记录、首次原型、签名 APK、构建日志、夹具与生命周期测试脚本在忽略目录和私有保全目录中。本项未向 Git 加入签名私钥、真实设备身份、原始日志或 APK。
