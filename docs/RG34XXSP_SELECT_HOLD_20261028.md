# Select 长按鼠标呼出

2026-10-28 开始修改，2026-10-29 完成实体确认。基于 `81772f7`，检查点 `baseline/rg34xxsp-select-hold-20261028`（沿用开始日期）。Navigation 更新为 **v7 / 1.4-select-hold**，作为数据分区 APK 更新安装；原系统内置 v5 和原交付 IMG 不变。

## 当前操作

**单独按住 Select 至少 2 秒，然后松开，切换鼠标。** 判断在松开时完成，再延迟约 100ms 切换覆盖层焦点；不是按住期间立即进入。可按约 3 秒后松开以留出余量。开启时光标回到屏幕中央，并显示“鼠标已开启”；关闭时显示“鼠标已关闭”。B 仍可直接退出鼠标。

- Select 少于 2 秒时仍把原按下、抬起和 downTime 交给应用；没有合成或重新注入应用按键。
- 同一控制器上，其他按键先按住，或在 Select 按住期间再按其他键，均取消本次长按。松开其他键不会重新计时，必须先松开 Select，再开始下一次。
- 因此 Select＋Start 的两个按下顺序均不触发鼠标。L1＋R1＋Start 旧呼出组合已经移除，肩键、Start 正常交给应用。
- 退出、锁屏、服务销毁等会取消待切换动作；已由鼠标消费的按下仍保留抬起所有权，避免孤立事件漏入应用。
- 鼠标关闭时，独立长按 Select 的原始事件也会先交给应用，所以应用自己的 Select 长按动作仍可能发生；增加阈值和排除组合键不能保证与所有应用的独立长按功能完全隔离。
- 组合取消基于按键事件；不承诺把所有应用中的摇杆/HAT motion 都作为“另一个按键”来取消长按。

鼠标移动仍用十字键或双摇杆，A 点击/长按，X 加移动拖动，Y 加方向滚动。本轮没有改全局键表、摇杆模块或 ROCreader。

## 变更原因与肩键边界

用户实体验收中多次报告旧三键组合不能可靠呼出，因此改用单键长按。此前一次读到 `mouseMode=true` 并截到箭头，只能证明那个时刻处于鼠标模式，不能据此判定实体三键组合已稳定通过。

ROCreader 的 `H70034xxSp` 与通用 H700 的 SDL joystick 布局确有差异，例如 L2/R2 的索引不同；SDL joystick 索引、Linux EV_KEY code 和 Android keyCode 是不同层，不能直接据此交换 Android 肩键。底层 getevent 记录未取得有效样本，后改用只记录自身窗口事件的 H700InputProbe。用户明确给出的操作顺序为 **L1、L2、R2、R1**，所得映射如下：

| 实体键 | Linux scanCode | Android keyCode / 名称 |
| --- | --- | --- |
| L1 | 308 | 102 / BUTTON_L1 |
| L2 | 314 | 104 / BUTTON_L2 |
| R2 | 315 | 105 / BUTTON_R2 |
| R1 | 309 | 103 / BUTTON_R1 |

这一轮与当前 Android 键表一致，没有发现肩键颠倒，未修改全局键表。R2 记录中有一次额外完整按下/抬起，不据此认定为硬件抖动。旧三键组合不稳定的根因仍未查明；新的呼出方式不再依赖肩键。

## 实现与验证

`MouseHotkey` 按设备独立跟踪 Select 的开始时间、其他已按键和取消状态；重复 DOWN 不重置计时，重复 UP 不重复触发。`MouseController` 保留原始 Select 事件对，待 UP 交还应用后再移动焦点，鼠标内则消费完整 Select 事件对。

当前 `Generic.kcm` 会把未被应用处理的 Select 转成 MENU。使用同一 scanCode=310 且带 `FLAG_FALLBACK` 的 MENU 作为 Select 的重复投递处理，避免将同一按键误判成另一个组合成员。实际 Menu 键和 Start 的 DPAD_CENTER fallback 不按此规则处理。

已完成：

- 5 组 Java 主机测试通过。长按测试覆盖 1999/2000ms 边界、重复 DOWN/UP、Select＋Start 两种顺序、不同设备、取消、清理、时间倒退和旧肩键组合不触发。
- 使用固定低压力入口构建 H700Navigation：CPU 0-1、合计 1 核、6GiB 内存、512MiB swap、nice 19、idle I/O；没有整系统编译。
- API 29 签名验证通过，保留数据安装后 APK SHA-256 回读一致。
- 测试夹具中，0.08/0.85/1.8 秒 Select 不触发，原事件时间保留；Select＋Start 两种顺序即使持有超过 2 秒也不触发；旧肩键组合不触发。
- 按住超过 2 秒但尚未松开时不切换；松开后进入，应用收到完整 Select 事件对。鼠标内长按关闭时没有 Select 事件漏给应用；另做 2 轮开关。
- A 点击/长按、X 连续拖动及静止拖动抬起、Y＋方向滚动、拖动中 B 退出通过；夹具收到 6 个 DOWN 和 6 个 UP/CANCEL，没有遗留触点或手势拒绝。
- AT4K 中的未处理 Select/MENU fallback 路径也已实际验证，2.2 秒后松开可进入，光标位于 720×480 屏幕中央 `(359.5,239.5)`，B 可退出。

2026-10-29 用户明确确认：长按 Select 后肉眼能看到光标、能移动，并能用 B 关闭。服务同步记录约 3010ms 的长按接受、光标坐标变化和最终鼠标关闭。此项完成了实体常用路径验收；全部应用、所有按键组合、长时间压力与跨重启恢复未在本轮重跑。未将旧三键失败描述成“已修复肩键映射”。没有重启、刷卡、改分区或清应用数据。
