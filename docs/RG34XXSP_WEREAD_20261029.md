## 登录与阅读结果

原机没有此包，新增安装成功；没有卸载或清除其他应用的数据。用户自行扫码登录，本轮没有代登录、购买、分享、创建笔记或主动添加书签。使用已有可读中文书籍验证，私人书架、账号和阅读记录没有公开。

| 流程 | 结果与限制 |
| --- | --- |
| 登录入口 | 标准方向键/确认键能勾选协议、到达“获取二维码”并生成二维码；用户完成微信扫码 |
| 书架 | 上下方向键能移动书籍焦点；左右键会滚动书架分页，不能直接据此证明横向选书。连续向下继续滚动书架，未证明可直接转入底栏；本次到“我”、设置和目标书籍使用了触摸注入 |
| 界面字号 | 设置 → 字体大小中，用方向键和 Enter 调到“小”，B 返回可用；只影响应用 UI，正文另设字号 |
| 正文排版 | 正常打开、自动重排；字体面板中实际字号从 22 调到 20，再到 19，页面总数随之变化；保留原字体、字重、行距和边距。正文缩小使用了触摸注入 |
| 标准方向键翻页 | 右下一页、左上一页，往返能回到原内容 |
| 当前控制器 HAT | 直接向已核对的 ANBERNIC-keys 注入 HAT_X=+1/0、-1/0；下一页内容变化，上一页与起始可见正文描述完全一致，以 SHA-256 比较确认。这是 evdev 链路测试，用户尚未亲手复核本轮手感 |
| 工具栏 | Menu/Enter 未能直接呼出；Select 单独长按 2s 后松开进入虚拟鼠标，Y+十字键下触发向上滑动，可显示工具栏 |
| 目录 | 鼠标模式下通过十字键移动光标、A 点击目录成功；B 关闭鼠标后目录保留，再按 B 返回正文工具栏。目录中的方向下仍把焦点留在后方正文，未通过完整按键选章 |
| B 返回书架 | 在正文工具栏状态，控制器 scan 305 的按下/抬起能够退出阅读，回到书架 |
| 进程重启续读 | force-stop 后启动，主进程 PID 改变；自动回到同一正文页，可见正文内容哈希完全相同，不需要重新扫码 |

上表包含标准按键、真实控制器 evdev 事件和直接触摸注入，分别注明；不能合并为“全程十字键通过”。虚拟鼠标的上滑和 A 点击均实际完成手势，没有新增取消或拒绝。

### 横屏未通过

书架和正文均观察到 **480×720**，自然屏为 **720×480、213dpi**。APK 中虽然有“阅读时横屏”“使用音量键翻页”等文案，但本轮可见设置没有找到对应横屏入口；不能把共享文案当成该墨水屏版本实际提供的功能。

为排除此前旋转设置的影响，保存当时 accelerometer_rotation=0、user_rotation=3，临时写入自然横向 0。正文仍为 480×720，随后读值重新为 3，窗口状态明确显示当前应用请求 `SCREEN_ORIENTATION_PORTRAIT`。具体回写方未定位，本轮未改签 APK 或修改框架来强制方向。

测试后已恢复并核对原旋转设置；没有改变密度或分辨率。**只能确认本轮未能开启横屏，不能推广为所有微信读书版本都不能横屏。**

## 保留配置与结论

当前保留：UI 字号“小”、正文字号 19，其余字体排版项不变；应用停在已恢复的正文，虚拟鼠标关闭。系统旋转已恢复测试前值。字体重排会改变显示页码，不应把不同字号的页码直接相互比较。

单次登录页 TOTAL PSS 140,810KiB，进程重启后正文 TOTAL PSS 109,434KiB，均无 swap；这些短采样不是长时性能、续航或 1GB 设备验收。音量键翻页、完整搜索/导入、全部设置、完整目录选章和离线阅读未验收。导入入口指向手机版 App 或电脑网页传书，没有在本轮上传新书。

**结论：官方 ARM32 墨水屏版能运行，正文可缩小、控制器左右可翻页、重启可续读；当前需要接受竖向界面和虚拟鼠标辅助，不推荐作为这台横屏掌机的全程十字键主力阅读器。** 本地 EPUB/漫画继续优先采用已记录的 KOReader 方案。

后续若继续适配，应先确认横屏能力及目录/工具栏焦点，再考虑应用专用的按键辅助。
