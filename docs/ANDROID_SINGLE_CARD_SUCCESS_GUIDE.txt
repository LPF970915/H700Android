【1. 分区布局 - GPT方案】
分区方案必须严格按照以下8分区结构：

Partition 1: special       (offset 0x2000,     size 0x800000)     # 8 MB
Partition 2: boot-resource (offset 0x802000,   size 0x1800000)    # 24 MB
Partition 3: env           (offset 0x2002000,  size 0x800000)     # 8 MB
Partition 4: boot          (offset 0x2802000,  size 0xA000000)    # 160 MB
Partition 5: system        (offset 0xC802000,  size 0x200000000)  # 8 GB
Partition 6: vendor        (offset 0x20C802000, size 0x80000000)  # 2 GB
Partition 7: data          (offset 0x28C802000, size 0x400000000) # 16 GB
Partition 8: ROMS          (offset 0x68C802000, size 0x8FC000)    # 9 MB

GPT头位置: offset 0x200 (512 bytes)
GPT备份表: 卡末尾倒数第二个扇区 (offset CardSize - 1536)

【2. Boot.img结构 - 自包含完整启动】
Boot.img必须包含完整的启动组件，不依赖外部分区：

结构布局:
  - Android Boot Header (2048 bytes, offset 0)
    * Magic: "ANDROID!" (8 bytes)
    * Kernel size, ramdisk size, second stage size
    * Load addresses
  
  - Kernel Image (offset 2048)
    * Linux 4.9 for RK3288
    * 大小约6-8 MB
  
  - Ramdisk (紧跟kernel之后，页对齐)
    * Gzip压缩的根文件系统
    * 包含init可执行文件和init.rc脚本
    * Gzip magic: 0x1F8B
  
  - Device Tree Blob (紧跟ramdisk之后，页对齐)
    * rk3288-h700.dtb
    * 包含硬件设备树定义

验证要点:
  ✓ offset 0: "ANDROID!" 魔数存在
  ✓ ramdisk偏移处有gzip头 0x1F8B
  ✓ boot.img总大小 < 160 MB (适配boot分区)

【3. Ramdisk Init脚本 - 单卡挂载逻辑】
Init脚本必须正确挂载单卡上的所有分区：

关键挂载命令 (init.rc 或 init.rk3288.rc):
  mount ext4 /dev/block/by-name/system /system ro
  mount ext4 /dev/block/by-name/vendor /vendor ro
  mount ext4 /dev/block/by-name/data /data noatime nodiratime

重要修改点:
  ✗ 错误: 不能依赖 /dev/mmcblk1 (TF2不存在)
  ✓ 正确: 使用 /dev/block/by-name/xxx (by-name由内核从GPT生成)

验证方法:
  1. 解压ramdisk.gz: gunzip < ramdisk.gz | cpio -i
  2. 检查init.rc或init.rk3288.rc
  3. 搜索 "mmcblk1" 或 "mmcblk0p" 确保没有硬编码设备节点
  4. 确认使用by-name路径

【5. 写入方法 - Git Bash dd工具】
使用dd工具进行扇区级精确写入：

工具路径: C:\Program Files\Git\usr\bin\dd.exe
权限要求: 管理员权限
设备路径: \\.\PhysicalDrive<N> (N为磁盘编号)

写入步骤:
  1. prefix-212m.bin → offset 0 (包含GPT+special+boot-resource+env+boot)
     SHA256: BCCA9BA02E60CB34843D88FBE69BE77CE69D309E0D1096421E12829A4B5743F5
     dd if=prefix-212m.bin of=\\.\PhysicalDrive3 bs=1M conv=notrunc
  
  2. system.img → offset 212 MB
     dd if=system.img of=\\.\PhysicalDrive3 bs=1M seek=212 conv=notrunc
  
  3. vendor.img → offset 8404 MB
     dd if=vendor.img of=\\.\PhysicalDrive3 bs=1M seek=8404 conv=notrunc
  
  4. data.img → offset 10452 MB
     dd if=data.img of=\\.\PhysicalDrive3 bs=1M seek=10452 conv=notrunc
  
  5. roms-metadata.bin → offset 26832 MB
     SHA256: 836E674B8038FA813EBB4392CFCB391ED2AA230B086A0686C6F5FA3A9A1D7649
     dd if=roms-metadata.bin of=\\.\PhysicalDrive3 bs=1M seek=26832 conv=notrunc
  
  6. gpt-tail.bin → offset (卡末尾-1536字节)
     SHA256: 1CC7B395088B92E2EAAD8ADB0D9E1B31E80BB9970CDB7B0C01265D1CD92D95F6
     dd if=gpt-tail.bin of=\\.\PhysicalDrive3 bs=512 seek=121560694 conv=notrunc

关键参数:
  - bs=1M: 块大小1MB，提高写入速度
  - conv=notrunc: 不截断目标文件，保留现有数据
  - seek=N: 跳过N个块后开始写入

══════════════════════════════════════════════════════════════════════
第二部分：踩过的坑与解决方案
══════════════════════════════════════════════════════════════════════

【坑1: 双卡依赖问题】
现象: Init脚本尝试从mmcblk1挂载分区，但单卡系统中TF2不存在
解决: 修改init.rc，将所有mmcblk1路径改为by-name路径

【坑2: Windows写入访问拒绝】
现象: PowerShell和Win32 API均无法打开\\.\PhysicalDriveN (错误代码5)
原因: USB可移动设备有特殊保护，无法设置离线状态
解决: 使用Git Bash的dd工具，在管理员权限下直接写入

【坑3: GPT分区表损坏】
现象: U-Boot无法识别分区，卡在"No partition table"
原因: GPT头或备份表写入位置错误
解决: 精确计算GPT备份表位置 (CardSize - 1536 bytes)

【坑4: Boot.img外部依赖】
现象: U-Boot找到boot分区但无法加载kernel
原因: Boot.img不包含完整的kernel/ramdisk，依赖外部文件
解决: 使用自包含的boot.img，确保kernel+ramdisk+dtb都在内部

【坑5: Ramdisk解压失败】
现象: Kernel启动后卡在"Failed to execute /init"
原因: Ramdisk.gz的gzip头损坏或偏移错误
解决: 验证ramdisk在boot.img中的偏移，确保gzip魔数0x1F8B存在

【坑6: 分区UUID不匹配】
现象: Android init找不到system/vendor/data分区
原因: fstab中的分区UUID与实际GPT中的UUID不一致
解决: 不使用UUID挂载，改用by-name路径（内核自动生成）

第三部分：标准化制作流程
══════════════════════════════════════════════════════════════════════

【阶段1: 准备源镜像】
1. 从成功的TF2安卓测试卡提取system.img和vendor.img
2. 准备单卡专用data.img (16 GB空白ext4镜像)
3. 提取boot.img并验证其自包含性
4. 提取U-Boot分区 (special + boot-resource + env)
5. 准备ROMS元数据
6. 计算并生成GPT备份表

【阶段2: 修改Init脚本】
1. 从boot.img提取ramdisk.gz
2. 解压ramdisk: gunzip < ramdisk.gz | cpio -i
3. 编辑init.rc或init.rk3288.rc
4. 将所有mmcblk1改为by-name路径
5. 删除对TF2的任何依赖
6. 重新打包: find . | cpio -o -H newc | gzip > ../ramdisk-new.gz
7. 重新构建boot.img

【阶段3: 构建Prefix镜像】
将以下组件按顺序拼接成prefix-212m.bin:
  - GPT主表 (offset 0x200, 16KB)
  - special分区 (offset 0x2000, 8MB)
  - boot-resource分区 (24MB)
  - env分区 (8MB)
  - boot分区 (160MB, 包含修改后的boot.img)

【阶段4: 验证源文件】
1. 计算所有源文件的SHA256
2. 验证GPT头签名
3. 验证boot.img结构
4. 验证ramdisk gzip头
5. 验证system.img ext4魔数
6. 保存验证清单到manifest.json

【阶段5: 识别目标磁盘】
1. 插入USB读卡器
2. 执行: Get-Disk | Where-Object BusType -eq USB
3. 通过序列号或容量确认目标磁盘编号
4. 记录: \\.\PhysicalDrive<N>

【阶段6: 执行写入】
在管理员PowerShell中执行:
   = "C:\Program Files\Git\bin\bash.exe"
   = "/usr/bin/dd"
  
  # 写入6个范围
  &  -c " if=prefix-212m.bin of=//./PhysicalDrive3 bs=1M conv=notrunc"
  # ... 依次写入其他镜像

【阶段7: 回读验证】
1. 验证GPT头 @ offset 512
2. 验证boot.img @ offset 0x2802000
3. 验证system.img @ offset 0xC802000
4. 验证GPT备份 @ 卡末尾
5. 使用Get-Partition确认8个分区存在

【阶段8: 上机测试】
1. 安全弹出USB读卡器
2. 插卡到H700 TF1
3. 串口监听
4. 上电观察
5. 等待Android UI (2-3分钟)
