# H700 Android 10 完善与验收路线

日期：2026-09-15，Asia/Shanghai。
范围：当前 RGSP 测试机、Android 10 / API 29 / ARM32 主线、TF1 单卡系统。
性质：文档与源码复核、设备只读采样后的建议执行计划，不是验收通过声明。

本轮未修改设备设置、未卸载挂载、未重启、未刷卡、未运行长时或破坏性测试。
没有重新运行 v5f 的 69 项历史测试，也没有重新计算完整镜像哈希。
只新增本报告，不覆盖历史文档，不修改实现代码或既有用户改动。

## 1. 总体判断

项目已越过“Android 能否运行”的阶段，具备桌面、GPU 渲染、Wi-Fi、
基础无触摸操作、软件媒体和 ROMS 公共存储的实现与部分实机证据。
当前主要缺口是：运行版本不统一、启动/关机持久性未闭环、硬件后端验收不足、
输入流程未全覆盖、1 GiB 内存策略未落实，以及发布安全和恢复机制尚不完整。

不应把所有未验收功能都重做，也不能把 APK 存在、HAL 注册、单次截图、
注入手势完成、历史开机时长或离线测试通过当成整机验收。

建议明确三个目标，避免“完整安卓”无限扩张：

| 目标 | 完成定义 |
| --- | --- |
| A：RGSP 日用测试版 | 可靠开关机，基本电源/亮度/音频/网络可用，不依赖 ADB 完成系统与目标应用操作，数据和存档可保存 |
| B：RGSP 可发布完整版本 | A 加上产品范围内全部硬件能力、正式回归、安全收口、可复现构建、升级/恢复及许可审查 |
| C：H700 多机型平台 | B 的方法推广到独立校准的其他屏幕/输入/电源配置，每个机型单独验收 |

本轮建议先完成 A，再关闭 B 的发布门槛；不以 GMS、Android 大版本升级、
双 ABI、DRM 高清或全机型通用作为 A 的前置条件。
如果蓝牙、HDMI、振动等暂不纳入 A，必须明确标为“不支持/未验收”，
不能把它们算作“完整硬件已适配”。

## 3. 本次设备只读事实

### 3.1 运行版本不是完整 v5f

- Git 主线：`7803a51`，2026-09-14 的 v5f 集成提交；鼠标改动尚未提交。
- v5f 镜像清单：`OFFLINE_VERIFIED_READY_FOR_FLASH`，物理启动未验收。
- 设备 `sys.boot_completed=1`，ROMS 为 `public:179,8 mounted`，
  `sys.rgsp.roms=ready`，系统根和 vendor 主挂载只读。
- 实机 vold、services.jar、ROMS handoff 的 SHA-256 与 v5f 清单相符。
- `/system/etc/preferred-apps/at4k-home.xml` 和
  `/system/media/wallpapers/IMG_3111.jpg` 在实机缺失。
  这不否定当前桌面可见或已选择壁纸，只证明工厂系统文件与 v5f 不一致。
- 当前导航 APK 从 data 侧多层 bind mount 到系统路径。
  其版本是 `1.1-mouse-test`，v5f 清单中的导航仍为 `1.0`。
- 因此应称“旧系统基础上集成组件和鼠标测试版的运行现场”，
  不能称“全新刷入 v5f 后的最终验收机”。

### 3.2 内存、电源与安全

```text
ro.product.cpu.abilist=armeabi-v7a,armeabi
ro.config.low_ram=true
MemTotal=996480 kB
MemAvailable=528040 kB  (单次采样，不是压力测试)
SwapTotal=0 kB
/proc/swaps 只有表头
CONFIG_SWAP=y
CONFIG_PSI=y
CONFIG_ZSMALLOC=y
# CONFIG_ZRAM is not set
init.svc.lmkd=running
activity_manager/max_cached_processes=8

persist.vendor.hwc.software_vsync=true
screen_off_timeout=2147483647 ms
stay_on_while_plugged_in=0
init.svc.console=stopped
init.svc.rgsp-console=running

SELinux=Permissive
ro.adb.secure=0
ro.debuggable=1
ro.secure=0
service.adb.tcp.port=5555
ro.build.version.security_patch=2019-12-05
```

具体含义：

- fstab 写有 `zramsize=75%`，但实际内核未启用 ZRAM，也没有 zram0。
  不是修改一个容量参数就能生效；PSI 节点存在，LMKD 正在运行。
- 原 ROMS 修复把未设置时的 cached-process 上限从 3 调到 8，
  已解决一次 provider 重启循环，但尚未证明重负载下整体内存可靠。
- 熄屏超时约 24.85 天，不能用这个测试设置证明正常自动熄屏/休眠。
  修改前须核对其是否仍属测试残留，不能盲目覆盖后来的用户偏好。
- health/audio HAL 有注册，AXP2202 battery/usb sysfs 存在，
  BatteryService 能报告电量、电压和温度；尚无本轮充电变化/物理测量验证。
- HIDL 枚举未见 power/light/vibrator/bluetooth 专用服务；
  vendor 有 `power.default.so`、`vibrator.default.so`。
  这些是后端审计线索，不等于已证明相关功能全部缺失或完全可用。
- ADB 实际为 root 且无认证；当前 IPv4 防火墙仅放行开发主机的 5555，
  IPv6 的 5555 被阻断。不能描述成已向任意网络开放，也不能当作生产安全。
- 2019-12-05 是系统声明的补丁级别，不是对实际回移补丁的完整审计。
- 本次 uptime 约 44 小时，只说明此内核会话尚未重启，
  不证明 framework/应用没有重启，也不替代正式 60 分钟监测。

## 5. 推荐逐项执行顺序

优先级含义：

- P0：数据、可恢复启动、整机可靠性和发布安全门槛。
- P1：日用和掌机目标应用的完整操作链。
- P2：产品范围内的扩展硬件与体验完善；若宣传支持，则发布前仍必须通过。
- P3：第二机型、架构升级及非首版必需功能。

下列次数是建议验收门槛，不是已完成次数。
两次正常重启、十次冷启动、六十分钟监测继承现有计划；
二十次交互/唤醒循环、大库规模和延长运行是本次建议的补充测试。

### G00 / P0：冻结真实基线与恢复条件

**当前**：v5f 镜像、运行中的组件升级、未提交鼠标源代码不是同一版本。

**工作**：建立设备/卡/boot/kernel/DTB/system/vendor/APK 的版本清单，
明确每项是持久文件还是临时挂载；保留当前 APK、挂载清单及用户数据备份。
核验现存恢复卡与镜像，不能引用已经删除的旧文件作为回退。
保留当前受限 ADB 调试通道，不擅自关闭唯一可靠的观测路径。

**通过条件**：任一运行组件可追溯到源代码与产物；当前可用状态可恢复；
已验证安全的救援/换卡流程；所有挂载、首启标记和用户偏好有明确处置方案。
建立本报告的执行回执，不手工把旧镜像清单改成“通过”。

### G01 / P0：启动、正常关机、ROMS 检查和首启扩容闭环

**当前**：已知 FAT/FSInfo 修复进入新 ramdisk，但 v5f 无首刷/重启实测。
旧 ramdisk 的 ROMS handoff 兼容路径也没有完整设备重启验收。

**工作**：在备用测试卡验证已冻结镜像，从完整上电 UART 到桌面记录；
检查首次扩容、vold 唯一 FAT 挂载所有权、关机卸载顺序、重启后数据。
若故障仍在，依据关机与下一次启动日志定位，不重复无依据地清 dirty bit。
设计 ROMS 不可用时的可诊断恢复入口；仅在系统/data/GPT 安全、
且不存在未完成扩容时评估降级进入系统，不绕过存储保护。

**通过条件**：空白工厂数据首启无需命令修复；无 HOME 选择器和重复扩容；
至少两次正常 Android 重启及一次关机后启动成功，测试文件和设置保留；
后续最终基线上再完成 G11 的十次冷启动。
首轮至少覆盖已使用的 64 GB/128 GB 两档实卡，再按发行支持范围扩展。

**禁止**：不在唯一工作卡做断电实验，不热拔系统 TF1，
不把中断 FAT 扩容标记删除当作恢复，不用通用 GPT 工具覆盖特殊启动区。

### G02 / P0：基本电源、背光、合盖与物理显示可靠性

**当前**：电池数值可读；正常自动熄屏仍被超长超时设置遮蔽；
历史有非用户触发的 power_button 睡眠记录，换机后不闪的报告不是软件修复证据。

**工作**：核对实际 power/lights/health/thermal 后端与 AXP2202/panel；
在经确认的正常超时配置下测电源键、锁屏/解锁、合盖/开盖、背光调节、
正常关机、充电接入/拔出和低电行为。分别记录 framework、原始电源事件
与相机画面，区分正常灭屏、错误休眠和面板/背光闪烁。

**通过条件**：五档亮度有实际、单调且可恢复的变化；电量/充电状态随实物变化；
电源键与合盖各二十次循环无误触、黑屏或无法唤醒；
唤醒后输入、音频、Wi-Fi 和 ROMS 恢复。
低电与温控只在安全、可观测条件下验证，不通过调电压或关闭保护排错。

### G03 / P1：统一实体键、原生焦点和虚拟鼠标

**当前**：基础导航可用，但 A 仍使用 RGSP 的 ENTER 适配；
鼠标在普通模式也消费 Select；按住 A 时光标不动；
长按只是固定时长触摸，不是持续接触。没有拖拽/滑动/多指实现。

**工作**：明确普通 UI、文本编辑、鼠标、游戏四种输入语义；
修正 Select 短按透传或采用明确可配置的模式键，不破坏游戏按键。
补齐 A 短按、持续按住、释放、移动拖动、列表滑动与退出取消；
加入设备切换、丢失释放、按住方向切模式、服务中断和锁屏的状态机测试。
优先完成单指能力；双指缩放单独决定映射和范围，不再宣称能模拟所有触屏行为。

**通过条件**：Settings、Files、目录授权、输入法、AT4K 与至少一个触摸型应用
真实完成点击、长按、滚动、拖动；二十次进出模式无卡键/重复动作；
普通模式 Select 与游戏 A/B/方向键不受破坏；
屏幕边缘/旋转/尺寸变化不越界，实际触点与光标尖端对齐。
640x480、720x720 当前仅有坐标测试，不冒充这些机型整机验收。

### G04 / P1：首启与系统日常操作全流程

**当前**：语言、基础 Files、Wi-Fi 输入曾被物理接受；复杂路径缺覆盖。
v5f 的工厂默认配置尚未在全新刷入的设备上确认。

**工作**：用普通实体键，必要时使用正式鼠标模式，从 HOME 进入设置、
修改语言/时间/音量/亮度、管理应用、浏览文件、打开 APK、允许安装来源、
确认安装、首次权限弹窗、启动和返回；同时覆盖最近任务、搜索、
长列表、上下文菜单、多选、文件名/对话框小屏裁切。
保留 Launcher3/恢复桌面；用户改 HOME、IME、主题后不被首启脚本重置。

**通过条件**：至少一个新增测试 APK 和一次正常更新流程完全不依赖
ADB、root、显式 activity intent 或触屏；允许/拒绝权限两条路径均可退出；
重启后用户选择保留，桌面异常时有实际可操作的恢复入口。
使用明确的无个人数据测试应用，不卸载用户现有应用来制造“首次安装”。

### G05 / P1：ROMS、应用存档、容量显示和第二 TF 槽

**当前**：v5f 已解决 ROMS 不可见问题，不能重列为“尚未挂载”；
内部显示 32 GB 是原容量统计语义，ROMS 扩容不增加应用安装空间。

**工作**：验证目标文件管理器/模拟器的实际 SAF 或受支持目录访问、
存档写入、目录授权重启保留、改名/删除、中文和长文件名；
大目录和磁盘满时必须能报错并保留旧文件。
整理 internal/data 与 ROMS 的统计口径，不能简单把 32 改成整卡容量。
单独实现/验收 TF2 扩展卡识别、安全卸载和拔出后的应用恢复。
FAT32 大文件限制和所支持文件系统要明确；exFAT 未验收前不作承诺。

**通过条件**：普通应用非 root 的文件操作与真实游戏存档重启后校验一致；
ROMS 异常不允许格式化系统卡；格式化/分区保护先在副本或模拟设备验；
至少五千项测试库扫描无 provider 循环崩溃/OOM；
TF2 的插拔不影响 TF1 系统/ROMS，复制失败不把未完成文件当成功。

### G06 / P1：Wi-Fi、时间、WebView 与离线能力

**当前**：历史联网和 HTTPS 已成功；本轮 Wi-Fi ADB 在线；
这不代替重新连接、跨休眠和跨启动验证。

**工作**：测保存网络恢复、开关、弱信号/AP 暂不可用、DNS/HTTPS、
系统时间与时区、无网启动、离线文件安装。
国内网络探测失败与实际外网可用分开显示和诊断；
不靠关闭 TLS 校验或强行标记 VALIDATED 掩盖错误。
WebView 版本/证书兼容和更新来源列入安全审查。

**通过条件**：物理输入连接可复现；十次 Wi-Fi 开关及多次唤醒/重启后可重连；
本地应用在无网或错误时间时仍可进入和退出；
目标 HTTPS 页面真实打开，失败原因能区分且不会引发系统崩溃。
热点、P2P、WPA3 作为独立能力，不从普通 STA 联网结果推导。

### G07 / P1：声音与音频生命周期

**当前**：旧版本修复过声卡权限/mixer，曾有人耳确认；
当前版本没有完整输出与电源循环验收，HAL 注册不等于听得到。

**工作**：先扬声器与硬件音量键，再按实际接口测耳机/USB/蓝牙/HDMI 路由；
检查静音、低音量、前后台切换、两应用抢占和休眠恢复。
保持现有 H700 mixer/权限修复，不能回填 donor 整套音频路由。

**通过条件**：从低音量开始的测试音和真实音乐/游戏均有人耳确认；
适用的输出插拔十次无串音、爆音或无声；
播放、停止、切换、休眠、唤醒和重启后均能恢复，
音频 HAL 无重复崩溃且设备权限不会退回错误值。

### G08 / P1：1 GiB 内存、帧时间和持续负载

**当前**：ZRAM 未编入运行内核；LMKD/PSI 可用；后台缓存 8 只通过有限测试。

**工作**：先量化 Launcher、system_server、媒体 provider、模拟器的 PSS、
PSI、LMKD 杀进程原因和前后台恢复；再决定并落实 ZRAM/无 swap 策略。
启用 ZRAM 需要可复现且匹配当前硬件的内核/模块方案；
没有该条件时先调低内存策略并验证目标负载，不随意更换已验证内核。
不把常规 TF 卡交换文件当默认解法。
检查 GPU/ION 资源、纹理缓存、温度/降频与帧时间；软件 VSYNC 可继续保留，
是否替换由撕裂、延迟和功耗实测决定，不为追求形式上的“原生”重开图形移植。

**通过条件**：文件选择器/provider/桌面不会因后台策略反复重启；
压力下优先牺牲可恢复后台，不损坏数据，不形成 system_server/SF 崩溃循环；
二十次应用切换后内存/句柄/图形资源无持续增长趋势；
记录并满足每个目标模拟器的实际性能目标，不承诺所有 PSP 游戏满速。

### G09 / P1-P2：真实应用与其余硬件

**应用工作**：建立 API29/ARM32/无 GMS 兼容清单，选定 RetroArch、PPSSPP、
音乐、阅读和文件管理样本；包括安装、控制映射、选 ROM、运行、存档、
退出、重开读取，而不只是“APK 启动成功”。

**硬件工作**：按设备能力逐项完成蓝牙 UART/固件/rfkill/HAL、
蓝牙手柄和音频、振动 PWM、USB 数据/OTG、HDMI 显示/音频/热插拔。
健康/温控的真实保护和充电属于 G02，不下放到可选美化项。
不支持的硬件 feature/VINTF/设置入口要准确，不能用假服务掩盖缺失。

**通过条件**：目标应用各自二十次运行/退出/重读存档无资源泄漏或卡键；
支持的外设完成连接、断开、休眠恢复与按键/声音/显示的实物验收；
未实现能力公开列为限制，不能计入“全功能版本”。

### G10 / P0 发布门槛：安全、可复现构建与升级恢复

此项从 G00 开始做清单与最小暴露控制，完整加固在核心功能稳定后集成；
不是发布前最后一天才开始，也不立即在唯一测试机强切 enforcing。

**安全工作**：开发版/发行版分开；收紧 ADB 默认暴露并启用认证；
移除生产 root console/测试入口；按实际设备标签完善 SELinux 并验证 enforcing；
审查存储、GPU/ION/disp/PWM 权限；验证 Keymaster/Gatekeeper 软件回退的真实边界。
审计内核、framework、WebView 的补丁来源与维护能力；
未具备可信启动/加密链时明确限制，不宣称已达到现代设备安全水平。
准备独立发行签名密钥和可升级签名策略，不把公开 test-keys 当正式凭证。

**工程工作**：把通过验收的鼠标和各运行修补纳入可重建产物；
核验 WSL 源码、补丁、内核/DTB、工具链、预编译 APK 与许可证。
使用现有低压构建入口；执行两次干净构建并比较关键内容，
记录时间戳/签名等非确定性来源，不未经验证宣称镜像逐字节可复现。
提供版本清单、哈希、刷卡校验、首启容量说明和已知问题。

**恢复工作**：首版至少具备可验证的救援、数据导出、重刷和回退流程；
完整 raw 镜像刷写会覆盖 data/ROMS，不能称作无损更新。
保留数据升级需单独设计事务/失败恢复；不能自动擦除 data 或 ROMS。
恢复出厂设置须确认清除边界并在可丢弃测试卡验证，避免误清 ROMS。
A/B OTA 可后置，但缺少 A/B 不能成为没有恢复方案的理由。

**通过条件**：发行配置重新通过功能回归；恢复卡/包可实际救回设备；
从干净源输入能重建规定内容；无测试覆盖、私有网络凭据或用户数据进包；
APK/壁纸/固件/运行库来源和再分发许可完成审查。
无授权材料不因已纳入私人开发镜像就自动获得公开分发资格。

### G11 / P0 发布门槛：最终基线统一回归

**前置**：G01-G08 的日用项关闭；声明支持的 G09 能力通过；
发行目标还需 G10。使用同一已冻结版本，不能拼接不同版本的通过记录。

**通过条件**：

- 十次真正关机后冷启动，不以 framework restart 或继续执行 `/init` 替代。
- 两次正常 Android 重启，首启配置、网络、ROMS 文件、游戏存档均保留。
- 六十分钟有连续证据的混合负载监测，覆盖内存、进程、温度、显示、
  音频、存储和网络；建议追加四小时日用测试，但不替代标准六十分钟记录。
- 电源键/合盖、应用循环、外设循环达到各自门槛，无未解释失败。
- 错误 APK、损坏图片/文件、磁盘满、无网、异常应用退出可安全恢复。
- 中断扩容/异常断电只在明确授权的备用卡或副本测试，保留原始证据和回退。
- 无 ADB 的物理用户流程通过，不能把注入事件测试计作这一项。

某项失败即记录失败、定位并局部修复；重新验受影响链路，
不保留与新版本不匹配的旧“通过”。

### G12 / P3：多机型和架构扩展

先选一台不同屏幕比例的设备做第二套 kernel/DTB/panel/input/power/audio
manifest。640x480/720x720 坐标适配不等于这些整机已经兼容。
有摇杆型号需要独立量程/死区/设备映射；不得复制 RGSP 的固定设备判断
或依赖所有同 VID/PID 设备具有相同按键语义。

每个机型重复 G01-G11 的适用门槛，共用 system 层但保留准确硬件 profile。
硬件视频解码、HDMI 扩展、双 ABI、大版本 Android 和更复杂 OTA 按独立项目推进，
不回引 Android 11 framework 绕过补丁，不直接套 H618 整套 vendor。

## 7. 紧接着做什么

1. 先完成 G00，保存现机混合版本和鼠标试验的准确回执及恢复输入。
2. 先在备用介质完成 G01 的首启、两次正常重启和文件保留门槛。
3. 进入 G02；与此同时可做 G03 的主机侧状态机开发，但同一真机的
   电源、输入、存储变更串行验证，避免无法定位回归原因。
4. G03/G04 通过后，用户能独立验 G05-G09，不再需要 ADB 代做点击。
5. 每个有实际验收结果的里程碑再整合镜像，最终执行 G10/G11；
   不为每次光标外观修改重复全系统刷写。

本轮不建议继续以桌面美化/指针发光为主线，也不建议从头重做已通过的
Wi-Fi 驱动、ROMS 暴露、基础键盘或 Mali 首图。
