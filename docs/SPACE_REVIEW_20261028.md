**原文件仍在。** 自动审批拒绝删除上述三个已被验证压缩包替代的原文件，返回 `blocked by policy`，未给出具体理由。未换工具重试。用户可在确认三个 `.gz` 均已保留后手动删除表中的三个原文件；这会释放约 40.21 GiB。不要删除整个最终阶段目录，里面还有 sparse 镜像及锁定凭据。

## 源码与编译的边界

当前开发树 `/home/lpf/h700-android10/android` 基于 H616 厂商源包，包含 H700 实测修改，必须保留。`prebuilts/` 约 30 GiB 是工具链和基础输入，不按编译缓存删除；上游源码压缩包也保留。

两套树的 `out/` 编译目录已删除，共 53,507,792,896 字节（49.83 GiB 的 Linux 分配量）。删除前确认没有编译进程，364 个冻结源文件全部一致、关键 Mali 输入位于源码树而非待删输出。小型构建输入/日志保存在私有压缩档案。下一次构建需重新生成图、主机工具及中间文件，耗时会增加，仍使用原低压力构建入口。

早期 `/home/lpf/H700Android/h616-android10-full` 与当前树逐文件比较；所有独有/不同的普通文件和旧符号链接先保存到私有差异档案，校验后再移除该停用副本。逐文件 SHA 清单用于追溯；差异档案不是独立完整源码包，恢复仍需保留的上游输入/当前基线。

`/home/lpf/roc_build_work/ROCreader` 按用户要求保留。它占约 11 GiB，属于同一 WSL 虚拟盘内的另一项目；本轮没有清理其源码、Git 历史、书籍、构建或依赖。

删除 Linux 文件释放的是虚拟盘内部空闲块。随后执行同步、TRIM 和当前 WSL 支持的 `wsl --manage Ubuntu --compact`，才能核对 Windows 上的实际回收量；执行结果以本轮最终凭据为准。未改虚拟盘容量上限、分区或文件系统大小。

命令能力同时核对了本机帮助与 [Microsoft WSL 命令实现](https://github.com/microsoft/WSL/blob/master/src/windows/common/WslClient.cpp)。本轮 Git 检查点为 `baseline/h700-storage-trim-20261028`；原始源码冻结标签保持不变。

## 完成后的实测结果

WSL 压缩命令正常返回 0，VHDX 当时降至 78,939,947,008 字节。重新启动 Ubuntu 并核验后为 78,973,501,440 字节（约 73.55 GiB），少量启动写入导致与刚压缩完成时略有不同。

项目文件合计从 261,395,771,688 字节（243.44 GiB）降至 154,033,447,767 字节（143.45 GiB），本轮净减少约 100 GiB；统计包含新压缩包与私有差异档案，三个原始镜像仍在。数据是本轮记录时的快照，后续 Git 提交、日志和 WSL 写入会有小幅变化。

| 剩余内容 | 大小 |
| --- | ---: |
| WSL：当前完整源码/工具链、ROCreader 和 Linux 环境 | 73.55 GiB |
| `out/`：三个原始镜像、压缩包、最终 sparse、原始证据和依赖 | 45.00 GiB |
| 原始上游包和 `input/` | 24.46 GiB |

旧副本共核对 761,993 个普通文件，761,950 个与当前树内容一致；43 个不同文件合计 1,842,966 字节，与 9,221 个旧符号链接保存为 606,141 字节的私有 tar.gz，另存全文件 SHA 清单。当前原生开发树未变。

重启后的 364 文件源码锁零差异，关键 Mali 输入哈希一致，ROCreader 的 Git 提交与回收前一致。5 项源码恢复测试通过；私有保全目录既有文件在更新清单前全部重新核验。本轮未重编译 Android。

完整数值和三个压缩包的 SHA 见 [结构化凭据](storage-review-20261028.json)。如果用户手动移除上表压缩记录对应的三个原文件，预计项目还可降至约 103.25 GiB；压缩包、最终 sparse、源码及私有输入继续保留。
