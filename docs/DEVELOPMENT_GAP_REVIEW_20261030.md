# 对照早期开发计划：v6b 之后的剩余工作

日期：2026-10-30。目标：RG34XXSP / H700 / 2GB / Android 10 ARM32。比较的是当前开发证据与新镜像候选，**离线封装通过不等于新镜像上机验收通过**；不以不同版本、不同机器的测试拼成整机通过，也不给缺少统一口径的百分比。

## 原始依据与范围调整

历史文档只从冻结 Git 标签读取，没有恢复旧树或执行旧脚本：

- [最早的持续开发计划，8-27 起](https://github.com/LPF970915/H700Android/blob/baseline/h700-v5i-usb-network-20261028/docs/H700_ANDROID_CONTINUOUS_DEVELOPMENT_PLAN.md)：目标为可扩展 H700 平台；其中 Android 11 headless 记录已明确归档。
- [9-02 Android 10 总计划](https://github.com/LPF970915/H700Android/blob/baseline/h700-v5i-usb-network-20261028/docs/H700_ANDROID10_MASTER_PLAN_20260902.md)：A10-P0～P4，先可重复构建、启动/存储、图形，再掌机基本功能与产品化。
- [9-15 完善与验收路线](https://github.com/LPF970915/H700Android/blob/baseline/h700-v5i-usb-network-20261028/docs/H700_ANDROID10_COMPLETION_ROADMAP_20260915.md)：将目标细化为 G00～G12，并给出冷启动、运行时长、外设及发布门槛。

旧的 TF1 Linux / TF2 Android handoff 方案后来已转为单卡；不把回到旧双卡布局当成必修任务，但可用的救援/回退仍要验收。Android 11/H618 混合移植不是待补功能。原计划以无 GMS 为主线，谷歌组件是后续新增、可选需求，不能冒充旧计划必选项；当前仍只离线准备、未集成/登录。多机型、双 ABI、DRM/完整电视能力属于后置扩展。保留 ROCreader 源码不等于本轮要求把所有 ROC 应用移植进 Android。

## 按总计划定位

| 原阶段 | 当前达到哪里 | 尚未满足的退出条件 |
| --- | --- | --- |
| A10-P0 可重复构建 | 完整外部源与覆盖层保留、组件/源配置锁、低负载入口和可校验镜像封装已有 | 两次干净源码构建的关键内容对照；当前横屏 services.jar 的完整源码 framework 重编仍未验收；不能只靠 Git clone 重建全部输入 |
| A10-P1 init/存储 | 单卡已运行，USB ADB、system/vendor/data/ROMS 基础链路可用 | 新 v6b 工厂首启、正常关机/重启、冷启及数据保留闭环；不能把旧机历史启动次数计给新镜像 |
| A10-P2 图形 | Mali/GLES、720×480 桌面和游戏画面已工作，软件 VSYNC 基线保留 | 同一新镜像连续 60 分钟显示/负载及冷启无黑屏；物理闪烁、帧时间与睡眠恢复；硬件 VSYNC 未恢复 |
| A10-P3 掌机基本功能 | AT4K/输入法/系统导航、鼠标、双杆、横屏；音乐/阅读/视频/模拟器基础工作流具备 | 亮度、完整电源/合盖与背光、续航/充电/温控、耳机、蓝牙、1GB 压力和应用完整操作链仍未闭环 |
| A10-P4 媒体/产品化 | 八款预装选择与配置、天马 G 媒体适配、软件解码预览及镜像锁已具备 | 通用硬解/DRM 能力边界、发行安全/许可、可恢复升级、多机型与双 ABI 等未完成 |

结论：基本显示与交互 bring-up 已越过；当前在 **A10-P3 收尾与 P4 初期**。能继续日常开发和做应用实测，仍不足以宣布“全功能、低功耗、可公开分发的正式发行版”。

## 建议接续顺序

1. **先验 v6b 新卡首启**：八款安装与配置、AT4K HOME、NOVA 手机/平板模式、空 ROM 库提示和复制自有游戏后的媒体/启动；再做正常重启和文件保留。此报告不授权自动刷写当前工作卡。
2. **先关可靠性缺口**：亮度五档；实体合盖/开盖及电源键循环；审查 Hall 唤醒源和 bringup 锁后再谈深度待机，同时量化充电/温度/电量。不能先移除唯一恢复路径后强制挂起。
3. **补齐日用链路**：用户已有的 3.5mm 耳机优先；音频/网络/ROMS 跨睡眠恢复；八款应用实际业务与实体导航复验。
4. **再做性能与扩展**：RA/PPSSPP 代表游戏长时测试、内存与帧时间；1GB 单独实测；蓝牙栈、TF2/MTP/OTG/HDMI/振动按支持范围逐项补齐。
5. **最后统一发行**：源码 framework 全量重编与两次干净构建、发行安全/许可和恢复路径；冻结同一版本后执行 G11。可选 Google、ARM64 与更多机型不阻塞当前 ARM32 主线。
