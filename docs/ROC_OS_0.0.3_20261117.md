## 包含的更新

- 十二机型启动菜单、保存默认和电源＋音量减重选，不按运存或摇杆数量限制启动。
- 35XX H 640×480、34XXSP 720×480、CubeXX 720×720 三档音量键试屏；选择具体型号后使用对应面板配置。
- 启动确认后显示“加载中，请稍后”，首次等待数据区和交换文件准备。
- Navigation18 与框架导航保护：处理熄屏、解锁、窗口变化、松开／回中及有界长按连发。
- 修正 H700 ADC 模式位的公共摇杆驱动，保留独立 L3／R3、中心校准、回中与有界恢复。
- 默认 2GiB TF1 交换空间、Lid4、时间默认源，以及既有 USB、ARM32 应用支持、生产签名和 user／Enforcing 配置。

十二机型及分辨率对应关系和首次启动操作见[当前版本说明](CURRENT_STATUS.md)。

## 摇杆修复依据

Test10 的 RG35XX H USB 现场确认：L3／R3 和十字键有原始事件，四个模拟方向轴为零事件；模块因 `reason=adc-control` 持续拒绝采样。现场 `CTRL=0x00890000` 已是正常连续模式，但旧检查错误使用第 8～9 位。

Test11 改为 H700 实际模式位第 18～19 位与启用位第 16 位，正确检查 `0x000d0000` 掩码及 `0x00090000` 期望值，保留其他控制位。实际 C 的 38 个正向场景、6 个冻结旧代码负控、1846 项检查、模块 ABI 和实际内核匹配，以及 45 个加载脚本场景通过。完整原理与原始 Test11 离线证据见[工程记录](ROC_OS_H700_ADC_CONTROL_REPAIR_TEST11_20261117.md)。

用户随后明确回复“本次修复有效”，并要求封装正式 0.0.3。该结果记录为 **RG35XX H 上 Test11 的用户实测确认**；本轮未新增 USB 原始输入采集，不据此声称全部有杆机型或熄屏恢复场景已完成验证。Test11 原有冻结离线收据保持原字节，实测补充单独记录。

## 使用与验证范围

使用至少 64GB TF1，首次测试 TF2 留空。只按电源首次进入菜单；默认 35XX H 640×480。若不可读，音量键切换三档试屏并重启返回菜单，再选择实际型号。确认后等待准备完成；首次创建 2GiB 交换文件需要时间，后续复用。

0.0.3 新封装包尚未另行刷机验收。Test11 的 RG35XX H 摇杆实测通过是本次发布依据，其他型号显示与摇杆、熄屏恢复导航、翻盖／休眠、USB 与校时等仍按实际新包反馈继续验证。默认交换空间已在 Test10 的 RG35XX H 现场确认为 `SwapTotal=2097148 KiB`，本包保留同一逻辑；它不能保证解决所有应用闪退。

源码与复核入口见[源码地图](TEST10_SOURCE_MAP.md)，公共自编流程与作者增量封装的范围见[构建验证状态](PUBLIC_BUILD_STATUS.md)。
