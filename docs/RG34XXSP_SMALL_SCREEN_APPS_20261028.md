# 720×480 小屏应用首轮筛选

日期：2026-10-28。基于 `7b0da03` 的 Navigation v6 / AT4K 日常开发状态；检查点为 `baseline/rg34xxsp-small-screen-apps-20261028`。只新增应用级配置和测试记录，没有构建系统、刷卡或更新原交付 IMG。

后续更新（2026-10-30）：用户已实测确认[首批六款预装名单](FIRST_PREINSTALL_BATCH_20261030.md)。NOVA 应采用**手机/平板模式**，用户反馈 TV 模式显示不全。本文以下 TV/mdpi 和候选建议保留为首轮历史事实，不再作为当前预装默认要求。

## 结论

小屏适配应同时检查正文重排、应用内缩放和按键可达性，不能只按“TV 版”筛选。720×480、密度 213 在 Android 布局中约为 541×361dp，TV 界面的大卡片、大留白和固定栏目容易挤占可读区域；文字没有溢出也不等于在 3.4 寸屏上容易读。

本轮下载并逐个初测 9 个 APK，**没有任何一个完成全部功能的纯十字键验收**。建议保留以下候选：

| 用途 | 优先候选 | 当前实际结果 |
| --- | --- | --- |
| 电子书 | KOReader 2026.07.1 ARM + 本仓库 H700 用户补丁 | EPUB 中文重排、目录选书、前后翻页、续读、B 返回通过；L1/R1 可缩小/放大字号。部分图形设置控件仍不可按键激活 |
| 漫画 | 同一 KOReader | CBZ 自动按屏宽显示；方向右依次移动到下半页、下一页，方向左回看，B 回目录通过；不是整页缩小后勉强阅读 |
| 视频 | Nova 6.6.2 ARMv7，预配置 TV + 应用内 mdpi | MKV/H.264/AAC 画面、中文字幕、A 暂停、方向跳转、B 返回和记录 0:52 续播位置通过；首次设置使用了调试入口 |
| 音乐 | VLC 3.5.6 ARMv7，暂作备选 | MP3、FLAC、暂停与切歌通过；TV 音乐页的窄列折行不适合这块屏幕，尚无合格的小屏音乐首选 |

这是远程事件注入和画面/运行状态验证。用户本轮不在设备旁，实体按键手感、长按节奏、实际听音、耳机与扬声器均未验收。本文中的“通过”只覆盖明确列出的路径。

## KOReader 的小范围适配

配置为 [2-h700-dpad.lua](../config/koreader/2-h700-dpad.lua)，安装与撤回见 [配置说明](../config/koreader/README.md)。只在 KOReader 内对 `RGSP H700` 型号生效，本轮仅验证用户提供的双摇杆样机；不更改 Android 全局键表、系统密度、ROCreader 或鼠标服务。

原输入后端没有把 joystick HAT 处理为阅读方向键。补丁启用已有 D-pad 焦点机制，将 HAT X/Y 边沿送给原有 Up/Down/Left/Right 处理，并丢弃该应用中原本会落入触摸路径的 joystick motion。真实触摸来源仍交给原处理器。摇杆没有新增阅读动作。

| 操作 | 按键 |
| --- | --- |
| 文件项目选择 | 十字键上/下 |
| 文件列表分页 | 十字键左/右；仅对单列文件列表应用这一规则 |
| 打开/确认 | A，沿用此机现有 ENTER/66，不误用 BUTTON_A/96 |
| EPUB 前后翻页、漫画按屏宽分段前后浏览 | 十字键左/右 |
| 关闭菜单；阅读中回文件浏览器 | B |
| 阅读菜单 | Select |
| 文件浏览器 | Start |
| EPUB 字号减/增 2 | L1 / R1；实测 22→24→22 和正文重新换行 |
| 阅读调整面板 | A；可打开，但不是所有面板控件均已按键可达 |

第一次启用会保存原 `back_in_reader` 值，再采用 KOReader 内置的 `filebrowser` 返回策略。后续用户显式修改该策略会保留。补丁使用优先级 2 的官方用户补丁机制；优先级 1 太早，曾触发初始化错误。试验失败配置及修正前证据仍在本地，不能把它们算作最终版本通过。

最终文件 SHA-256：`1246e5b3b9dcc2a82637c32664ea64b3538cd2174afbaff319cf064270b6d848`。设备文件与仓库文件一致，最终版本重新验证了 EPUB 前后翻页/B 返回、字号快捷键，以及从文件列表打开 CBZ、上下半页、跨页、反向回看/B 返回。

## 方法、数据和保留范围

- 使用已核对身份的 USB 样机。标准 Android 界面的方向测试主要用 `SOURCE_DPAD` 注入；A/B 用原控制器 evdev 注入。KOReader 最终流程的方向也走原控制器 evdev HAT。软件注入不替代实体验收。
- 每次操作后检查焦点或截图，不用触屏点击、虚拟鼠标或无障碍 CLICK 补过断路。观察器使用不暂停 Navigation 服务的配置，所有本轮捕获均要求 `mouseMode=false`。
- 测试目录只放自制内容：中英 EPUB、UTF-8/GB18030 TXT、8 页 CBZ/PDF/PNG、2 分钟 MP3/FLAC、640×360@24 的 H.264/AAC MP4/MKV 与中文字幕。生成不等于每种格式都已验证，实际覆盖见上表。[夹具锁](app-tests/rg34xxsp-20261028/fixture-lock.json)记录各内容哈希。
- 为统一 720×480 横屏条件，保存原旋转设置后临时设 `user_rotation=0`；结束恢复 `accelerometer_rotation=0`、`user_rotation=3`。密度始终为 213，未调整全局 DPI。Nova 的 mdpi 是它自己的界面选项。
- 原 v5i 的硬件解码限制仍然存在。VLC 此片源有 MediaCodec 打开及实际出图记录，不能由一个 H.264 片源推导所有编码、分辨率或应用的硬解都已修复。
- 拒绝 Nova/Kodi 的麦克风权限，不扫描 ROMS、不下载商业内容、不加入媒体账户。测试结束停止全部 9 个试验应用，返回 AT4K，鼠标关闭；候选应用及自制夹具仍在数据分区，没有预装进系统。

[APK 锁](app-tests/rg34xxsp-20261028/apk-lock.json)包含 9 个确切版本的官方分发 URL、体积、SHA-256、包名、ABI、最低 SDK、实际签名证书指纹和结果分类；[证据索引](app-tests/rg34xxsp-20261028/evidence-index.json)只保存自制内容截图的标签和哈希，原始画面及日志不上传。

本地 APK 位于 `out/tv-apps-20261028/apks/`，共 272,765,952 字节；没有另复制一套推荐 APK。生成脚本、私有操作记录、最终设置备份和文件清单另保全至 `LOCAL_PRESERVE_H700_BASELINE_20261028/app-selection-20261028/`。完整 APK/截图/媒体夹具仍在原 out 目录，保全清单不表示二进制已外部备份。
