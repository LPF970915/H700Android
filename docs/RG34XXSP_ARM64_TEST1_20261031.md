# RG34XXSP 首版 ARM64 测试镜像 Test1（2026-10-31）

目标为 RG34XXSP / H700 / 2GB：可重新刷写的 Android 10 ARM64 主架构、ARM32 兼容测试系统。使用此前 P1/P1b/P1c 已验证的官方 GSI 配套 framework/ART 与 H700 BSP 启动、厂商接口及图形组件，不代表完整 BSP 源码的 64 位 framework 重建。原 64GB 工作卡和 v6b 候选继续保留。

## A 键解锁

物理采样确认 A/B/X/Y 分别为 Linux 304/305/307/306。三个现用 keylayout 的 A→ENTER 映射正确，故没有交换面键。旧 BSP 的 `StatusBarWindowView.dispatchKeyEvent` 曾在子控件分发前专门接收控制器 A/Enter；GSI SystemUI 没有这段修改，因而出现 A 无效、Y 的菜单回退仍可解锁的差异。

Test1 从 Navigation v8 派生一个仅用于原型的版本 9，增加内部、不可导出的解锁 Activity：只匹配 rgsp 原型、ANBERNIC-keys、scan304/ENTER 的成对按下/松开，且仅在无密码锁屏时调用系统 `requestDismissKeyguard`。取消、重复、无配对松开不重复发起请求；安全凭据输入不被接管。没有改 GSI SystemUI 签名或 framework，也没有覆盖正式 Navigation v8 源码。

受控 sleep/wake→A 的检查通过，用户随后确认“已按 A 解锁”。这项实体确认来自刷写前的同一候选 APK；新镜像首启后的结果另记录，不能自动算作已通过。

## 固化内容

- 显式 VNDK29、Java heap128m/256m、软件 VSYNC，以及 P1c 运行标记；另加 `ro.h700.prototype.image=dualabi-test1-20261031`。
- 保留 P1b 相对 init 链接、ramdisk 兼容分区别名、唯一 GPT GUID 和私有 bootstrap loader。
- AT4K、原型导航及四个已锁定测试 APK：ARM64-only ABI probe、MT ARM64、RA32、PPSSPP ARM32。八款正式预装的全量迁移在后续阶段。
- 首启校验 APK SHA/指定 ABI，设置 HOME 和无触屏导航，授予两款模拟器所需存储权限；RA 种入既有控制器配置与绝对路径的最小配置，避免 `~/data/...` 路径回退。
- 首启安装使用内核文件锁和原子完成标记，完成后重启不覆盖用户配置。硬断电/安装中断恢复仍未验收。
- 蓝牙在首启安装阶段关闭，以避开已知 HCI 崩溃；没有把关闭当作修复。其他硬件、低功耗和正式发行配置尚未迁移验收。

镜像来自离线干净工厂尾部，不从当前卡复制 userdata。无 ROM、BIOS、账号或存档；官方测试核心与 cube.elf 也不打入镜像。实体采样、解锁前后、旧安装状态与 RA 测试配置在重刷前留本地保全。

## 构建与校验

```powershell
.\tools\build_h700_low_pressure.ps1 -Targets H700DualAbiTestNavigation -Execute
.\tools\build_h700_low_pressure.ps1 -Targets H700DualAbiTestImage -Execute
.\tools\build_h700_low_pressure.ps1 -Targets H700DualAbiTestAudit -Execute
py -3 -X utf8 .\tools\write_h700_dualabi_test1.py
```

最后一条默认只显示计划；只有明确授权的 128GB 备用卡、精确原卡/备用卡 CID、USB/profile、动态块节点、无挂载/holder 和镜像审计都匹配后，`--execute` 才写卡。出现已开始的记录时禁止重放；`--verify-only` 只读回。该范围不包括写原工作卡。

构建保持 CPU0–1、合计单核、`-j1`、nice19、6GiB RAM、512MiB swap、低 I/O 优先级。校验覆盖固定父范围 SHA、每个修改文件的内容/标签/权限/属主、文件系统、继承的 GSI framework/ART、compact GPT、完整 gzip 解压及所有范围 SHA。不会生成另一份 32GB 整卡 raw。
