## 修复内容

导航升级为同包生产签名的 Navigation17（`2.3-axis-guard`）。服务分别管理设备、来源、HAT/摇杆的方向状态；熄屏、亮屏、解锁、失焦、窗口或设备变化会停止旧连发；回调清理后不能自行重新排队。连续轴导航最多 10 秒，到期需松开再按。保留正常的 400ms 首次延迟及随后 160ms 连发。

被动选框刷新不再触发焦点或滚动动作，相同边框不重复请求重绘。该变化降低无意义的图形更新，不能据此宣布整屏频闪已修复。详见 [导航修复与运行记录](ROC_OS_NAVIGATION_FIX_20261114.md)、[唤醒路径复核](ROC_OS_NAVIGATION_WAKE_PATH_20261114.md)及[故障分析](ROC_OS_NAVIGATION_FLICKER_ANALYSIS_20261114.md)。

新增资源型静态覆盖 `ROCTimeDefaults`，把首次启动读取的框架默认 NTP 源设为 `ntp.aliyun.com`。此源在同一台34XXSP网络探测中两次有效响应；实际系统框架的普通 product 策略 idmap 映射与查询通过。已有显式 `Settings.Global.ntp_server` 设置仍优先。Android10 单例只在初始化时读取服务器，因此默认资源在首启前生效；联网仍取决于网络与服务器可达。详见[时间问题分析](ROC_OS_TIME_SYNC_20261114.md)。

## 封装与验证

system 文件级变化严格为：新增一个校时 APK，修改导航 APK 与 `build.prop`，删除旧导航 `.odex/.vdex`。旧预编译缓存移除后由 Android 按新 APK 生成代码。两份新 APK 都通过 API29 签名、生产 platform 证书及对齐核验。完整 gzip 解压读回、各分区范围、ext4 检查、实际包内容和安装标签均经独立核验。

bootloader、启动环境、kernel、DTB、vendor、userdata 与备份 GPT 保持 0.0.1 字节。沿用原 720 启动/显示路径、默认 `mtp,adb`、user/Enforcing 及既有诊断 ADB 公钥预授权。该包保留0.0.1的诊断 userdata；公共自编流程会新建空 userdata，两者的身份不可混用。未执行 Android 全量重编。

公共源码同时更新覆盖层版本、RRO 模块发现与包清单，并将准备目标、构建收据、最终打包绑定到当前源码清单；旧清单或手工改动的准备树会被拒绝。当前清单1757项目标中624个仓库来源逐项核对通过，11项公共工具测试通过；公开入口的干净完整 Android 重编仍保留待验状态。

## 运行验收边界

Navigation17 已在现有34XXSP上完成原位更新、长按/松开及三次实体恢复解锁检查，均未出现持续滚动；LT/L2与RT/R2输入已确认。用户报告的偶发故障来自原0.0.1，多机型故障现场尚未捕获，不能把正常态观察当作原故障成功复现后消除。

完整0.0.2整卡尚未新刷启动；下次开机自动校时、RTC断电保时、低概率频闪、全H700机型/面板和既有电源/USB恢复问题仍需各自验收。新包不扩大0.0.1的显示兼容范围。烧录使用至少64GB专用TF1，会覆盖目标卡数据；备份和核对磁盘后按既有流程操作。
